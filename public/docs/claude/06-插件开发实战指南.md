# 插件开发实战指南 —— 从零到一个能跑的 dsh 插件

> 本文是 Claude 基于源码阅读的独立解读，非官方文档。官方对应：`docs/cookbook/`、`docs/user/develop/`。
> 本文面向"我们要在 dsh 上拓展更多有用/有趣插件"这个目标，给出选型决策、最小骨架和踩坑清单。

## 第零步：想清楚你的插件是哪一类

| 你想要的效果 | 插件形态 | 核心 API |
|---|---|---|
| 给模型一个新能力 | **工具插件** | `ctx.tools.register(defineTool(...))` |
| 拦截/放行/改写行为 | **hook 插件** | `ctx.on('tools/pre-execute', ...)` 等 waterfall |
| 接入新模型服务商 | **LLM 适配器** | `class extends LlmAdapter` + `ctx.llm.registerAdapter` |
| 换掉某个基础设施 | **Provider 插件** | 实现某接缝的 Service Provider（如 `ctx.fs`） |
| 给模型持续塞上下文 | **上下文插件** | `ctx.systemPrompt.section()` 或 `agent.inject()` |
| 新增人类斜杠命令 | **命令插件** | `ctx.commands`（不经模型） |
| Web 界面加面板/聊天行 | **客户端插件** | package.json `dsh.client` + slot/ConversationNode |
| 对接外部系统/协议 | **协议驱动** | 消费 `ctx.agents` + `session/event` |
| 定时/后台自动化 | **调度插件** | 定时器 → 空闲时 `followup()`、忙时 `inject()` |

## 最小工具插件（可直接照抄的骨架）

```ts
// my-plugin/src/index.ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'my-weather'          // 插件名（loader 行的 name 指向本包）
export const inject = ['tools']           // 声明依赖 → 服务就绪前不激活

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'get_weather',
    description: 'Query current weather for a city.',
    parameters: {
      city: { type: 'string', required: true, description: 'City name' },
    },
    output: {
      schema: { type: 'object', properties: { tempC: { type: 'number' }, desc: { type: 'string' } } },
      render: (_args, v) => [{ type: 'text', text: `${v.tempC}°C, ${v.desc}` }],
    },
    async execute(args, exec) {
      const res = await fetch(`https://api.example.com/w?city=${encodeURIComponent(args.city)}`,
        { signal: exec.signal })          // 必须尊重 exec.signal
      const data = await res.json()
      return { tempC: data.temp, desc: data.desc }   // 只返回规范 JSON 值
    },
  }))
}
```

要点回顾（详见 04 篇）：
- `register()` 是 effect，插件卸载自动注销——**不要**自己攒全局注册表。
- 参数由 schema 自动校验；DSL 表达不了的约束（非空、正数、跨字段）自己在 body 里查。
- **值与话术分离**：`execute` 返回程序值，`render` 负责给模型的说法。Code Mode 下模型拿到的是值，不是话术——把 `output.schema` 当 API 设计。
- 抛异常 = 基础设施故障（`isError`）；"业务上不理想"（如命中 0 条）是**成功值**的一种。

## 让它跑起来：三种挂载方式

```bash
# 1. 开发期最快：patch 覆盖（不动任何官方文件）
dsh --profile web --patch my-patch.yml
```

```yaml
# my-patch.yml —— 顶层是补丁数组
- insert:
    - id: my-weather
      name: my-dsh-plugin-weather        # 已 npm install 进 profile 的包名，或相对路径
```

```bash
# 2. 持久安装：写进 $DSH_HOME/cordis.patch.yml（家层，覆盖所有 profile）
#    或 $DSH_HOME/profiles/web/cordis.patch.yml（仅 web profile）
# 3. 只影响某类会话：写进 agent preset 的 agent.cordis.yml（注意 isolate 审计规则）
```

验证组合结果：`dsh --profile web --dump-config` 能看到你的行即成功；行卡在 `waiting for <service>` 说明 `inject` 里有服务没人提供。

## Hook 插件：五个策略点的选型

```ts
export function apply(ctx: Context) {
  // ① 可扩展允许/拒绝/询问（可被排序影响）
  ctx.on('tools/pre-execute', async (exec, next) => {
    if (exec.name === 'bash' && String(exec.arguments).includes('rm -rf'))
      return { kind: 'deny', reason: 'Dangerous command blocked.' }
    return next()                        // ← 不调 next 就短路了整条链！
  })
  // ② 不可推翻的最终否决
  ctx.tools.guard(exec => exec.name === 'write' && planModeActive ? 'plan mode forbids writes' : undefined)
  // ③ 包住派发：超时/重试/指标
  // ctx.on('tools/execute', ...)
  // ④ 改写结果/附加上下文
  // ctx.on('tools/post-execute', ...)
  // ⑤ 只读审计
  // ctx.on('tools/result', ...)
}
```

**头号坑：waterfall 忘记调 `next()`。** 返回而不委托 = 短路整条链（包括默认行为）。只观察不决策的监听器必须 `return next()`。

## 上下文插件：两条注入通道

```ts
// 通道 A：系统提示分节（每步组装时都在）
ctx.effect(() => ctx.systemPrompt.section({
  id: 'team-conventions', order: 50,
  render: () => readFileSync('CONVENTIONS.md', 'utf8'),
}))

// 通道 B：agent.inject()（一次性，进下一个被接纳的请求；不唤醒空闲 agent）
ctx.on('some/watcher-event', (file) => {
  for (const agent of ctx.agents.list()) {
    try { agent.inject(createUserMessage({
      content: [{ type: 'text', text: `File changed: ${file}` }],
      source: { kind: 'plugin', plugin: 'my-watcher' },
    })) } catch { /* agent 可能已销毁 */ }
  }
})
```

区别：分节 = 常驻声明式；inject = 事件驱动、落日志（`user/message`，source 区分）、回放可见。

## LLM 适配器（接新模型服务商）

```ts
class MyAdapter extends LlmAdapter {
  async *stream(options: GenerateOptions): AsyncIterable<StreamChunk> {
    // 把 provider 的 SSE 翻译成 block-start / text-delta / tool-call-delta / usage / finish
  }
}
export const inject = ['llm']
export function apply(ctx: Context, config: Config) {
  ctx.llm.registerAdapter(['my-provider'], new MyAdapter(config))
}
```

关键契约：**一切结局都收敛为一个终结 `finish` chunk**（`error`/`aborted` 也是），不跨流 API 抛异常。参考实现 `packages/llm/llm-deepseek`；官方指南 `docs/cookbook/adding-an-llm-adapter.md`。

## 仓库纪律清单（提 PR 前自查）

- [ ] 每个注册走 `ctx.effect()`/`ctx.on()`，有 disposer
- [ ] Config 用 schemastery 声明，部署可变项不硬编码（`DEFAULT_*` 不算）
- [ ] 新模型可见输入 = 新 `SessionEventMap` 事件（声明合并 + `@mode` JSDoc）
- [ ] waterfall 监听器调用 `next()` 委托
- [ ] 误配置加载时炸响，不静默跳过
- [ ] 跨界 id 用 `Branded<B>`
- [ ] 工具 UI 呈现是 `args`(+result) 的纯函数
- [ ] 非平凡改动附 Agent Note（`.agents/notes/`）；模型/用户可见行为变化补 keyless snapshot

## 📌 rc.8 增量：三个新的插件作者能力

1. **插件自有设置卡**（官方新 cookbook `adding-a-settings-card`）：一个包两半——host 半 `installSettingsSection(ctx, NS, Config, config, {...})` 注册命名空间（**注册即暴露**，白名单机制已删除），browser 半向 `settings.plugin.item` keyed slot 注册手写卡片（keyed 而非 list：没有兜底通用表单——"Nothing renders a form it was not given"，schema 反渲染会经 `toJSON()` 泄漏 secret 默认值）。写入走 `ctx.settingsScope.bind({ namespace })`，每次写以读到的 revision 做栅栏。
2. **实验包路径**：不确定的新领域可以进 `packages/experimental/`（命名 `@deepseek-ai/dsh-experimental-*`、private 不发布、发布包禁止依赖）——文档/测试/不变量纪律**一条不松**，毕业=原子改名搬家。给"想先跑起来再定契约"的插件一个有门禁的家。
3. **多实例 provider 组合**：subagent 提供方支持 `providerName`——同一 profile 挂两行 Claude Code（一行 `plan` 只读、一行 `acceptEdits` 可写），各绑一个 toolName，模型端看到两个语义不同的委托工具。这是"用组合行数表达策略差异"的新范式。

## 我们可以做的插件点子（结合本仓库机制的可行性标注）

**实用向**
1. **MCP 服务器桥的扩展**（已有 `dsh-mcp-client` 样例 `examples/mcp-memory`）——接入公司内部工具链只需一行 insert。
2. **代码评审插件**：`tools/result` 审计 fs 写入 + `agent/turn-stopping` 时汇总 diff 请求自评——纯扩展点组合，零核心改动。
3. **用量看板**：订阅 `assistant/message.usage` 折叠成本投影（参考 `session-projection` 单元模式），Web 端加一个 `dsh.client` 面板。
4. **国产模型适配器**（Qwen/GLM/Kimi）：照 `llm-deepseek` 的 OpenAI 兼容路径，工作量主要在 reasoning/tool-call delta 映射。
5. **企业审批流**：`ctx.approval` 的应答者可以是飞书/钉钉机器人——`approval/request` waterfall 挂一个监听器即可。

**有趣向**
6. **会话回放剧场**：日志天然支持 token 级回放（`assistant/chunk`），做一个"重演"UI 插件几乎零后端工作。
7. **Agent 对战/协作**：`ctx.subagents` 六种 provider 任选，让 dsh 驱动 Claude Code 和 Codex 干同一任务再互评。
8. **定时晨报**：cron 插件（参考 `examples/web-schedule`）空闲时 `followup()` 触发日报任务。
9. **自修改实验**：`tool-cordis` 已允许 agent 检视/挂载自己的插件——可以做"agent 给自己写工具"的演示。
