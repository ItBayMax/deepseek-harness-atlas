# 17 · 实验层与包分类治理

> 基线：`dsh@0.2.1-rc.2`（上游 commit `687f282`）· 本篇为 0.2.1 全新

本轮最大的结构性变化不是加了什么功能，而是**给"这个包凭什么留在仓库里"立了一道门禁**，
并由此诞生了 `packages/experimental/` 这一层。

顺带，它删掉了一整个子系统——而且**没有留下决策记录**。这一节单独写在最后。

## 一、包分类：被安装 ≠ 被使用

### 问题

依赖图里出现一个包，**不能证明它被随附 profile、运行时导入或可选能力真正挂载**；
反过来，一个嵌入式 SDK 或需要部署配置的 provider，即使不出现在默认 GUI 里，
也可能承担真实的维护职责。

### 规则

`packages/` 下每个**非实验**包，要么有"有效产品用途"，要么在策略表里显式列出一个
被审查过的职责。两者都没有 → 门禁失败，提示直接给三个出路：

> mount it, declare its maintained role, or move it to experimental

六个类别写死在策略文件里：

```ts
// scripts/product-package-policy.ts:1-18
/** Product role that does not require a default runtime mount. */
export type ProductPackageCategory = 'optional' | 'sdk' | 'build' | 'test' | 'web-distribution' | 'declarations'

/** One explicitly maintained package role and its reason. */
export interface ProductPackagePolicy {
  /** Why this package remains outside the experimental group. */
  readonly reason: string
  /** The supported product role checked against its directory. */
  readonly category: ProductPackageCategory
}
```

当前 31 条豁免。关键在于**类别与目录是绑死的**：`test` 必须在 `packages/test-support/` 下、
`sdk` 只能是 `packages/sdk/client`、`build` 只能是 `packages/typert/generator`……
所以这不是一张自由填写的豁免表，而是**六个有限命名空间**。

### 判定是双向的

```ts
// scripts/verify-product-use.ts:234-254（节选）
    if (entry.category !== 'web-distribution' && defaults.packages.has(path)) {
      failures.push(`${path} (${pkg.name}): stale ${entry.category} policy; default runtime use requires removing this declaration`)
    }
    …
    if (!defaults.packages.has(pkg.directory) && !optional.packages.has(pkg.directory) && policy[pkg.directory] === undefined) {
      failures.push(`${pkg.directory} (${pkg.name}): no product runtime use; mount it, declare its maintained role, or move it to experimental`)
    }
```

既拒绝"没用途也没声明"的包，**也拒绝"已经被默认挂载了却还留着豁免条目"的陈旧声明**。

> **教学价值**：大多数项目的豁免表是单向的——加进去就永远留着。
> 这里把"豁免过期"也做成失败，豁免表就不会变成垃圾堆。

### "有效用途"刻意排除了什么

门禁不读构建产物，只做**源码级可达性**，从 5 个 profile、`apps/web/index.html` 的
`<script type="module">`、动态挂载表出发递归解析。不算用途的有：

- **manifest 依赖不算**（光写进 package.json 没用）
- **纯类型引用不算**（`.d.ts` 和 `lib/` 路径被直接丢弃）
- **被禁用的组 / Include 行不算**
- **失效的 patch 行不算**（先应用 patch 再统计）
- **可选组合可达 ≠ 默认可达**，两者分开统计

## 二、experimental 层的契约

### 四条正交轴

`packages/experimental/README.zh.md:26-30` 把四件常被混为一谈的事拆开了：

| 轴 | 含义 | 是否表示成熟度 |
|---|---|---|
| **实验性** | 整个公开能力在评估中，不属于产品支持承诺，可变可撤回 | ✅ 这一条才是 |
| **可选** | 用户显式选择 | ❌ |
| **官方** | 项目维护并在插件页列出 | ❌ |
| **发布 / 默认安装 / 界面可见性** | — | ❌ |

反过来，实验状态**不放宽**什么，`packages/experimental/AGENTS.md:8` 一句话列全：

> Experimental status does not relax engineering, security, documentation,
> lifecycle, testing, or snapshot requirements.

实测佐证：47 个实验包**全部** `publishConfig.access: public`、**零个** `private: true`。
**"实验"≠"不发布"**，而且发布本身不构成稳定性承诺。

### 规模与搬迁

| | 0.2.0 | 0.2.1 |
|---|---|---|
| `packages/experimental/` 目录数 | **21** | **47** |
| 本轮 | 新增 27、删除 1（`schedule-bundle` 退役），净 +26 |

其中 **11 个是从正式包组整体搬过来的**，而且**保留了旧 npm 包名**：

`hook-protocol`、`hooks-claude-code`、`hooks-codex`、`tool-session-query`、
`session-title-all-prompts-llm`、`skill-badge`、`tool-terminal`、`webhook`、
`webhook-github`、`tool-ralph`、`cua`

⚠️ **后果：不能靠 npm 名判断一个包在不在 experimental 目录。** 必须走 `isExperimentalPackageName()`。

三个顶层包组因此**整体消失**：`packages/hooks/`、`packages/webhook/`、`packages/runtime-diagnostics/`。

### 隔离是单向的

```ts
// scripts/check-workspace-constraints.ts:593-614（节选）
        const experimental = experimentalNames.has(name) || isExperimentalPackageName(name)
          || /^(?:npm:|workspace:)/.test(range) && hasExperimentalPackageReference(range)
        if (!experimental) continue
        if (section === 'dependencies' && offered.has(name)) continue
        errors.push(`${manifest.name ?? dir}: ${section}.${name} must not reference an experimental package`)
```

- 正式包/apps **不得**在 `dependencies`/`optionalDependencies`/`peerDependencies` 里写实验包
- **实验包可以依赖正式包，也可以互相依赖**
- 测试可通过 `devDependencies` 用实验包
- **全局唯一例外**：`@deepseek-ai/dsh`（CLI）的 `dependencies` 可以列 `OPTIONAL_BUNDLES`
- 连 `npm:` / `workspace:` 别名里藏实验包名也会被抓

### 实验包反而有一项"特权"

```ts
// scripts/verify-plugin-record-callers.ts:36-37
/** Production source under this prefix may call the restricted function. */
export const EXPERIMENTAL_PREFIX = 'packages/experimental/'
```

`appendPluginRecord`（往 Session 日志写 plugin record）**只有实验包的生产源码可以调用**，
正式包不行。对应的持久化契约：这些记录是 ignorable、log-only，
**不进 known-event 集合、不进持久化 schema 指纹、不进兼容性历史；格式迁移只尽力保留**。

> 这是"实验层有独立且更弱的持久化保证"的机械体现——不是靠文档约定，是靠调用方门禁。

### 0.2.1 撤销了实验层的依赖豁免

原来 `verify-package-dependencies` 的扫描范围是 `packages/!(experimental)/*/package.json`——
整个实验组不受依赖声明规则约束。后果很具体：4 个实验 client 包把 `client`/`api`/`session`
写成 `peerDependencies`，webworker packer 沿 workspace peer 把这些包收进镜像，
浏览器静态库成了打包起点，打一个 profile 时冒出 **82 条无法解析的请求**。

复查 6 个带 `dsh.client` 的实验包，共 **46 条违规，全部出在实验包**。修复就是两行范围改写：

```ts
// scripts/verify-package-dependencies.ts:35-37
const RELEASE_MANIFEST_GLOB = 'packages/!(experimental)/*/package.json'
/** Every package group, experimental included, follows the same published dependency policy. */
const POLICY_MANIFEST_GLOB = 'packages/*/*/package.json'
```

## 三、`*-bundle` 到底是什么

**不是一种新的包类型，而是 manifest 上的一个字段 + 一个 profile patch 层。**

一个"纯 bundle"包的 `src/index.ts` 全文只有两行：

```ts
/** DSH badge skill profile layer; runtime entries are declared in cordis.patch.yml. */
export {}
```

载荷在 `cordis.patch.yml` 里：

```yaml
- insert:
    - id: skill-badge
      name: '@deepseek-ai/dsh-skill-badge'
```

### 与普通插件包的区别

| | 普通插件包 | bundle 包 |
|---|---|---|
| 载荷 | 源码/服务/工具 | 通常 0 行逻辑，载荷是 patch 文件 |
| 挂载 | 由 profile 决定 | **随安装交付但默认关闭**，必须先选中 bundle 才能配置它贡献的行 |
| 发现 | 靠包名 | 声明 `icon` + `./locale/*.json`，插件页"官方"分组展示 |
| 隔离豁免 | 无 | 列入 `OPTIONAL_BUNDLES` 后可被 CLI 的 `dependencies` 引用 |
| 组合能力 | 单个插件行 | 可插入 `cordis:group` 带 `isolate`，**自带隔离服务实例** |

最后一条才是 bundle 真正的表达力。`ralph-bundle` 隔离 `workflowEngine`（它要用自己的
spawn provider，不能污染全局 workflow 服务），`terminal-bundle` 隔离 `terminals`，
`session-search` 隔离 `sessionQuery` 并把 sqlite 配成 `path: ':memory:'`、`openAt: first-search`。
`terminal-bundle` 还用 `disabled: !!js process.platform === 'win32'` 做平台分支。

**bundle = 一个可开关的、带隔离边界的子组合**，不是"装几个包"。

### ⚠️ 命名不可靠

`OPTIONAL_BUNDLES` 当前 12 个，但 `session-search`、`auto-review`、`tool-worktree`、
`agent-team-profile`、`inspector-profile` 都是 bundle 却不叫 `*-bundle`。
**判据永远是 `dsh.bundle.patch` 字段**，不是后缀。

### 一个关键观察

`plugin-market-bundle` 是**实验包**，但它的依赖是两个**正式发布包**
（`boot/plugin-market` + `client/ui-plugin-market`）。

这解释了隔离规则为什么必须单向：**experimental 层承载的是"组合与交付的不确定性"，
不一定是"代码的不成熟"。**

## 四、`no-top-level-await`：一条规则的完整诞生过程

值得单独看，因为它展示了这个仓库"从一个 bug 到一条门禁"的标准路径。

**触发事件**：某个包在模块顶层 `await`，而这个文件同时是包的导出目标。
**浏览器 Preview 的模块加载器按 CommonJS 包装模块体，遇到顶层 await 直接拒绝打包**——
于是那个 bundle 进不了 webworker 镜像。全仓扫描发现共 4 处，**当时没有任何门禁阻止这种写法**。

**三条理由**：

1. 模块求值变成异步 —— 每个导入方的求值被挂住
2. 失败语义错位 —— 入口的运行失败变成"模块加载失败"
3. 无法降级成同步 CommonJS 包装 —— 浏览器 worker 镜像加载不了

**门禁的严谨之处**（值得抄）：

- 判定走 TypeScript AST，**最近的函数体是模块本身**的 `await` / `for await` / `await using` 全算
- **只排除 bin，且只按声明**：源文件以 `#!` 开头，或 package.json `bin` 指向的目标
- **语料防护**：语料为空、没有 `.tsx`、或某个含 TS 的 `src/` 完全没进语料 → **门禁报错**
  （防止 glob 失效导致静默放行）
- 规则正文写死"**例外：无**"

那条语料防护是最容易被忽略、也最该抄的一条：**一个只会"通过"的检查等于没有检查**。

**自认的代价也写了**：第三方包和 `apps/` 不在范围内。

## 六、⚠️ invariants 被删除：职责没有转移，是被放弃了

这一节必须单独写，因为**升级指南只说了"不再发布"，真正的交代不在任何现行文档里**。

### 原来它做什么

`ctx.invariants` 是一个与产品无关的服务，各产品包通过 `./invariant` 子路径插件注册检查。
它解决的是**单值不可变性管不了的那类问题——记录之间的关系**：

- `dsh-session/invariant`：seq 单调、turn/step 嵌套、tool-call/result 配对
- `dsh-agent/invariant`：合法的 agent-status 迁移
- `dsh-scope/invariant`：作用域事件 subject 正确分发
- `dsh-agent-loop/invariant`：**把循环构造的请求与"从 session 日志前缀重建出来的请求"逐字段比对**

### 删除的规模

commit `f028f25667`：**1355 files changed, −15409 行**。
删的不只一个包，还有 **20 个包的 `src/invariant.ts`**、4 个验证脚本、
`docs/subsystems/invariants.md`、`module-graph` 的 9 个节点。

### 职责去哪了

把那篇被同一个 commit 改写的决策记录前后对照，答案很清楚：

**改前**：
> The session log needs **two different protections**: immutable ownership of each
> stored fact, **and checks for relationships among facts** across time and service contracts.

**改后**：
> Immutability of individual values **does not establish relationships among records**.
> … Those rules relate multiple records or services, cannot be established by freezing
> one object, **and are outside this decision.**

从"契约的另一半"变成"**不在本决策范围内**"。整节 "Package-owned invariant companions
check relationships" 被删除，"Responsibility is split between…" 一句也被删除。

另一篇的改写更直白——那条"用全新 Session 独立重建请求并逐字段比对"的运行时交叉验证
**直接消失**，`docs/architecture.md` 里对应的句子从"**A runtime invariant checks** model
requests are reconstructable from the log"改成纯政策陈述"Every model request **must be**
reconstructable from the log"。

**从机械保证降级为评审规范。**

### 流程缺口

`docs/AGENTS.md` 规定 Agent Notes 承载"the why, what-was-given-up, and required verification"。
而 `f028f25667` 向 `.agents/notes/implemented/` 新增了 **0 篇**记录——只把 2 篇旧记录移进
`archived/`，而 `archived/AGENTS.md` 明确规定归档文件是
"frozen historical snapshots: **never edit them or treat them as current authority**"。

结果：**"运行时关系检查这件事被主动放弃"这个决策，在仓库里没有一个 current authority 的家。**
唯一能还原它的证据是两篇记录的 **diff**（不是现文）。

> **这是本轮最值得记的一条**：一个纪律严明到为"模块顶层 await"专门立门禁、
> 为"豁免过期"专门加检查的仓库，在删掉一个 15000 行的子系统时，
> 却漏掉了自己最核心的流程要求。
> **治理机制再密，也挡不住"删除"这个动作天然不触发任何检查。**

## 八、上游自身的文档漂移

1. **`PRIVATE_EXPERIMENTAL_PACKAGE_DIRECTORIES` 是一条没有成员的分支。**
   `packages/experimental/AGENTS.md:6` 写"只有该清单里的目录保持私有"，
   但该数组**是空的**，47 个实验包零个 `private: true`。文档把"机制存在"写成了"有私有包"的印象。

   `docs/AGENTS.md` 的检查清单明令禁止"手写目录清单"。

### 工具执行被拆成两条路

新增 `packages/core/tool-executor-native` 与 `tool-executor-ptc`（commit `455686626d`，2026-10-19）。

对工具作者的影响（`docs/upgrade-guide/v0.2.1-rc.2/tool-executor-plugins/guide.md`）：

- `@deepseek-ai/dsh-tools` 仍管注册与 executor 选择，但**在加载期拒绝 `mode` 和
  `maxParallelSubCalls` 两个字段**；自定义 composition **必须显式挂一个 executor，否则启动失败**
- **一个 scope 只允许一个 executor**，由"最近的 scoped executor"决定行为
- 环境变量 `DSH_TOOLS_MODE` **废除**，web / headless / sdk 一律从 base 继承 native
- 导入路径迁移：PTC SDK renderer 与 `CodeRunFailedError` 改从 `@deepseek-ai/dsh-tool-executor-ptc`；
  `ToolExecutionPipeline` / `executeToolBatch` 改从 `@deepseek-ai/dsh-tools/pipeline`；
  测试夹具改用 `@deepseek-ai/dsh-tool-testkit`

### 🔄 Python PTC 运行时被整个删除

我们此前写过「Python PTC 要求 `sandbox` 和 `sandboxPolicy`」。现在这条**不再适用**——
整个运行时没了（commit `d1cf1dede1`，2026-11-11，**−14701 行**，连录制语料一起删）。

现存 PTC 运行时只剩 `ptc-runtime` 抽象 + `ptc-runtime-node` 唯一后端。

**没有迁移去处，只有改写**（`docs/upgrade-guide/v0.2.2-rc.2/python-ptc-removal/guide.md`）：
外部 provider 报 `language: 'python'` 也会被拒（抛 `TOOL_CONTEXT_UNAVAILABLE`）；
Python `run_code` 程序必须改写成 TypeScript。
Node 后端的要求反而更多：除 `sandbox`/`sandboxPolicy` 外还需要 `fs` 和 `subprocess`。

> 不受影响的是 `python/sdk` 下的 Harness Python 客户端——那是另一回事。
