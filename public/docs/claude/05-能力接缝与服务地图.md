# 能力接缝（Capability Seam）与服务地图

> 本文是 Claude 基于源码阅读的独立解读，非官方文档。对应资料：
> `docs/capability-seams.md`（生成的服务图）、`docs/glossary.md`、各 `packages/*/*/README.md`。

## 接缝 = 三角色，缺一不可

dsh 给"可换能力"下了一个严格定义——一个 **seam（接缝）** 必须同时有三个角色：

| 角色 | 是什么 | 例（shell 接缝） |
|---|---|---|
| **Service Definition** | 拥有 `ctx.<key>` 与词汇类型的 Cordis Service（抽象类或具体注册表，**绝不是** TS interface） | `dsh-shell`（`ShellExecutor`） |
| **Service Provider** | 一个或多个实现 | `dsh-bash-local` / `dsh-bash-sandbox` / `dsh-pwsh-local` |
| **Consumer** | 注入并使用该服务的插件，常是模型工具 | `dsh-tool-bash` |

仓库纪律："只有一个角色不叫接缝"——新能力必须三角色一起设计。角色通常各占一包（独立演化），也允许一包多角色（如 `dsh-llm` 同拥 Definition + Consumer）。

## 为什么这个设计有杠杆

**换一个 provider，整个产品跟着走。** 最典型的是"执行世界"三件套：

```text
ctx.fs（文件） + ctx.subprocess（进程） + ctx.shell（bash）
   本地世界：fs-local + subprocess-local + bash-local
   E2B 远程沙箱：fs-e2b + subprocess-e2b（共享一个 ctx.e2b 句柄）
```

把 fs 和 subprocess 指到 E2B，**Bash、PTY 终端、LSP 全部自动跟着搬进远程沙箱**——因为它们全是 `ctx.subprocess` 的消费者，没有任何 provider 分叉。这是接缝纪律换来的最大红利。

同理 subagent 接缝：`ctx.subagents` 后面站着六种 provider——同进程 spawn/fork、ACP 子进程、**Codex CLI、Claude Code CLI**、dsh SDK 远程——模型工具 `tool-subagent` 完全无感知。dsh 可以把一个 turn 委托给另一个产品的 agent 去跑。

## 服务地图速查（按域分组）

以下按我理解的域分组（完整机器生成版见官方 `docs/capability-seams.md`）：

### 核心脊柱（core，不可换但可扩展）
- `ctx.sessions` — append-only 会话日志与内存 store
- `ctx.agents` — 活 Agent 注册表 + create/resume 工厂
- `ctx.agentLoop` — 唯一的具体循环驱动（扩展包依赖事件而非此包）
- `ctx.tools` — 工具注册表 + 守卫管线 + Code Mode
- `ctx.systemPrompt` — prompt 分节与工具 schema 组装
- `ctx.invariants` — 运行时不变量注册表（各包自带 invariant 伴生文件）

### 模型域
- `ctx.llm`（seam）— 适配器注册 + 统一流 API；providers: `llm-deepseek`、`llm-pi-ai`、`llm-replay`（测试回放）
- `ctx.tokenMeter` — 回放式 token 计量（压缩压力的输入）
- `ctx.compaction`（seam）+ `ctx.toolResultPruner` — 上下文压缩

### 执行世界
- `ctx.fs` / `ctx.subprocess` / `ctx.shell` / `ctx.terminals`（PTY）/ `ctx.lsp`
- `ctx.sandbox` + `ctx.sandboxPolicy` — 进程沙箱（macOS sandbox-exec / Linux landlock / Windows ACL），消费者交出 argv，backend 包装后报告执行情况
- `ctx.codeRuntime`（seam）— Code Mode 的程序执行基底（worker 线程实现）

### 交互与策略
- `ctx.approval`（seam）— 一次性审批 waterfall，**无应答者 = fail-closed**
- `ctx.userQuestions` / `ctx.commands`（人类命令，不经模型）/ `ctx.permissionPresets`
- `ctx.planMode` — 计划模式（日志态）

### 会话周边
- `ctx.sessionPersistence`（seam: jsonl / sqlite）、`ctx.sessionQuery`（+sqlite 全文检索）
- `ctx.sessionProjections` + `ctx.sessionProjectionCache` — 事件流折叠成 UI 状态（列表不用读全日志）
- `ctx.sessionTitle`（seam: first-prompt / all-prompts LLM）、`ctx.sessionTelemetry`（OTel）
- `ctx.storage`（seam: json/sqlite）→ `ctx.storageDomain` — 非会话数据
- `ctx.settings`（分层设置）/ `ctx.credentials`（**配置存引用，provider 存值**，轮换即时生效）

### 高阶能力
- `ctx.subagents`（六 provider）/ `ctx.jobs`（后台工作注册表）/ `ctx.workflowEngine`（工作流脚本引擎）
- `ctx.goals`（同会话目标）/ `ctx.skills`（技能目录：filesystem/badge providers）
- `ctx.web`（seam: exa/perplexity/deepseek 搜索 + http fetch）
- `ctx.spillStore` — 超大工具输出外溢存储（spill-policy 决定何时溢出）

### 宿主与自修改
- `ctx.webServer` / `ctx.apiProxy` / `ctx.clientModules`（浏览器插件图宿主）
- `ctx.typert` / `ctx.typertGateway` — 运行时类型注册表与 RPC 网关
- `ctx.dynamicCordisRunner` / `ctx.cordisInspect` — **agent 检视并挂载自己的插件**（tool-cordis）

## 📌 rc.8 增量（rc.5 → rc.8）：接缝地图的变化

**两个新 ctx key**：
- `ctx.agentTeams`（实验）——持久多代理协作域，叠在 `ctx.subagents` 之上（花名册/信箱/任务板全落 Lead 会话日志），详见 [08 篇](08-AgentTeams多代理协作.md)。
- `ctx.fileReferences` ——文件引用接缝：`dsh-file-reference` 定义（@语法/候选形状/模型指引），`file-reference-local` 实现（每 agent 一个有界模糊索引，工具结果事件触发失效）。会话引用继续走 `ctx.sessionReferenceResolver`。

**subagent 接缝四项产品化**（Codex / Claude Code 提供方）：
1. **具名实例**：Config 加 `providerName`——一个 profile 可挂多行 Codex/Claude Code（各配各的权限、env），每行绑一个唯一 toolName；**没有**模型可见的 provider 选择器。
2. **一次性后台**：产品工具行开 `backgroundMode: one-shot`，暴露通用 `run_in_background` 参数，任务生命周期完全复用 `ctx.jobs`（不造第二套状态）。
3. **非交互权限**：每提供方一个 `permissionMode`，用**产品原生词汇**（Claude Code: dontAsk/acceptEdits/auto/plan/bypassPermissions；Codex: never/approve-for-me/…）而不是自造统一抽象；模式**不进工具 schema**——模型输入永远无法提权。
4. **失败事实**：`SubagentResult.diagnostic`（≤4KiB 消毒后的结构化一行：product/stage/category/HTTP/exit/signal），映射钉版本的官方错误联合，未知值归 `unknown` 不抄原文。

**接缝支撑能力**（为 Teams 加的，通用可用）：`startContinuable({ childId })` 调用方预留子会话 id、`drainContinuableChildren()` 精确排空指定直系子代理。子代理报告投递模式改名 `wakeup → next-step`（改走 `parent.steer()`）。

**模型域**：
- `llm-deepseek` 支持**直连视觉输入**——能力按精确模型元数据 `inputModalities` 门控（缺 `image` 在任何 I/O 前抛错）；请求级图像总量 20 MiB 上界由供应商中立的 `offloadRequestImages()` 保证（最旧优先换占位符、纯函数、回放可复现）。
- **推理链回传修复**：`reasoning_content` 现在**每个带推理的轮次都回传**（原先只在 tool-call 轮）——不是省 token 的 bug，而是兼容"网关按哈希恢复思维签名"的场景；代价是推理轮多付输入 token，换来跨网关可重建。
- `llm-pi-ai` 加 **compat 漂移门**：30 个兼容字段逐一声明 offer/withhold，四层编译期锁定（上游加字段/漏声明/漏 schema 都编译失败）；未声明/被扣留/**空值**（YAML 裸键→null）一律**写入处拒绝**而不是静默丢弃。
- `BlockAssembler` 的 replay 状态升级为 `ReplayEnvelope`（response + 逐块 metadata **一次决策同拆同留**）——修掉了 max-tokens 截断导致会话**永久卡死**的对齐 bug；读侧从硬错误降级为单条消息 degrade + 诊断。

**执行世界**：`ctx.terminals` 后端 `terminal-bash` 加 `shellDialect` 双方言（bash/pwsh 同一 OSC 就绪协议）；`ctx.codeRuntime` 迎来 Python 协议层（见 04 篇）。

## 几条值得抄的接缝设计规范

1. **显式 resolve 优于隐式默认**：`dsh-shell` 的 request/spec 拆分是模板——把"补默认值"做成 owning 实现里的显式 `resolve(request): Spec` 步骤，而不是 `run()` 里藏 `?? default`。
2. **跨界 id 一律 branded**：`SessionId`、`CallId` 等都是 `Branded<B>`，编译期防串。
3. **配置炸响**：误配置在加载时（自包含时）或最早可解析点报错，绝不静默跳过。
4. **credential 按操作解析**：消费者每次操作时解析引用，轮换的密钥下一个请求就生效。
5. **无硬编码可调参数**：部署可变的选择必须是 `Config` 字段（cordis.yml 可改）；`DEFAULT_*` 常量不算可配置性。
